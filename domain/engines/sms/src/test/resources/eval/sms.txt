# Frozen bank-alert evaluation set (issue 3.9; SRS §18, §23, §21.5).
#
# Why:  §21.5 says AI evaluation runs against frozen labelled datasets whose regression thresholds
#       block merges. SmsEvalTest is that gate. Unlike the receipt parser, **the SRS puts no number
#       on SMS parsing** — the two thresholds this set enforces are ours, and they are deliberately
#       lopsided:
#
#         - amount + direction accuracy >= 95% on the transactional half;
#         - **100% rejection** of the non-transactional half.
#
#       The asymmetry is the whole point. A missed alert costs the user one manual entry, which is
#       what they were doing before this feature existed. A false positive puts money in their
#       ledger that never moved. So the second gate has no budget at all: one OTP, one loan advert
#       or one declined-payment notice becoming a draft fails the build.
# What: fifty anonymised messages in the templates Indian banks, cards and UPI apps actually send —
#       thirty real movements and twenty that merely mention money.
# Result: a keyword edit that starts admitting adverts, or stops reading UPI payments, fails CI.
# Changelog: 2026-08-07 — Created for issue 3.9.
#
# **What this set does and does not prove.** It was written alongside the parser, so its score is
# *not* an independent estimate of how the app performs against a real inbox — it is regression
# protection. Bank wording also drifts: a template that changes next year is not covered by any
# fixture written this year. The independent measurement is the emulator run against messages
# injected with `adb emu sms send`, and, in the end, the user's own review screen — which is why
# nothing here is ever saved without a tap (P-07).
#
# **A text file, not JSON, on purpose.** `:domain:*` is pure Kotlin with no serialisation dependency
# (ARC-002), so a JSON fixture would mean hand-rolling a parser in a test. This format is read by
# six lines of `split`, exactly as `eval/receipts.txt` is.
#
# **Every message here is invented.** No real person's inbox is in this repository, and no real
# account number, reference or phone number appears (P-01).
#
# Format: `# key=value` header lines, then the message body, then `===` on its own line.
#         expect = debit | credit | none.  amount = paise, empty when expect=none.
# =============================================================================
