# =============================================================================
# Golden file for nature classification (issue 4.3; SRS §8.3.1, §21.5).
#
# The acceptance criteria ask for "a golden-file test over a labelled fixture".
# Every record fixes an input and states BOTH the expected nature and the
# expected `CLS-NAT-*` citation, because a step that fires for the wrong reason
# and happens to land on the right nature is still a broken decision order —
# and it is the kind that stays broken until a merchant, an account or a
# category changes and the answer quietly turns wrong.
#
# Why a text file and not JSON: this module is pure Kotlin with no
# serialisation dependency by design (ARC-002), so the fixture is parsed by the
# test that reads it — the bargain eval/sms.txt and eval/categorisation.txt
# already struck.
#
# Format: records separated by a line of `===`, fields as `# key=value`:
#     account      one of AccountType's stored values          (required)
#     counterpart  the other side of a transfer, or omitted
#     type         expense | income | transfer_out | transfer_in | adjustment
#     amount       signed paise (MNY-001)                       (required)
#     category     a CategoryNature stored value, or omitted
#     median       the category's median magnitude in paise, or omitted
#     history      nature:count pairs, comma separated, or omitted
#     expect       the nature that must come out                (required)
#     cite         the CLS-NAT-* ids, comma separated, in order (required)
#     flagged      true | false — whether it reaches §8.3's review flow
# Any other `#` line is a comment, including this block.
# =============================================================================

# expect=liability
# cite=CLS-NAT-001
# flagged=false
===

# --- step 4: what the user already decided -----------------------------------
# Overridden to WANT three times, against a category that says NEED. A
# suggestion that keeps reversing a correction is not learning, it is arguing.
# account=bank
# type=expense
# amount=-95000
# category=need
# history=want:3
# expect=want
# cite=CLS-NAT-004
# flagged=false
===
# Two to one is not settled — 6 666 bps, under the floor — so it yields to the
# category rather than imposing a majority the user never agreed to.
# account=bank
# type=expense
# amount=-95000
# category=need
# history=want:2,need:1
# expect=need
# cite=CLS-NAT-005
# flagged=false
===

# --- step 6: the modifier ----------------------------------------------------
# §8.3.1's own example: ₹9,400 at a grocery whose median is ₹2,000. Festival
# stock-up (still a NEED) or a party (a WANT)? Only the user knows, so the
# nature is kept and the question is raised.
# account=bank
# type=expense
# amount=-940000
# category=need
# median=200000
# expect=need
# cite=CLS-NAT-005,CLS-NAT-006
# flagged=true
===
# Exactly three times the median is not yet unusual — the boundary is open.
# account=bank
# type=expense
# amount=-600000
# category=need
# median=200000
# expect=need
# cite=CLS-NAT-005
# flagged=false
===

# Purchase Advisor's problem, not the classifier's.

# type=expense

# category=want

# expect=want

# cite=CLS-NAT-004,CLS-NAT-006
# flagged=true
