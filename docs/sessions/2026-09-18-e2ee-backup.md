## 1 · Decisions this session

### 1a · Argon2id from BouncyCastle — the one primitive Tink lacks

SEC-005 names Argon2id; SEC-003 says Tink or platform APIs only. Tink has no password KDF at all, and
the platform has only PBKDF2. So both requirements cannot be met by Tink alone. The resolution keeps
SEC-003's intent — no invented construction — by taking Argon2id (RFC 9106) from a vetted library and
confining it: one internal `BackupKdf`, `implementation` in `:core:crypto` only. The cipher is still
Tink's `AesGcmJce`, which draws its own nonce.

**The KDF is checked against a different implementation.** OpenSSL 3.5 ships `ARGON2ID`; the two
known-answer vectors in `BackupCipherTest` came from `openssl kdf`, not from BouncyCastle, so the test
would catch a wrong parameter mapping (lanes vs threads, KiB vs bytes, the UTF-8 conversion) that a
self-generated golden value would bake in.

Rejected: PBKDF2 (not memory-hard, not what SEC-005 says), Lazysodium (native + JNA, not testable on
the plain JVM), hand-written Argon2 (SEC-003).

### 1b · Cost: RFC 9106's second option, carried in the file and bounded on open

64 MiB, t = 3, p = 4. In the header so a later build can raise it and still open old backups; bounded
(≤ 256 MiB, ≤ 16 passes, ≤ 16 lanes, salt exactly 16) **before** anything is derived, because `open`
reads the cost from an attacker-supplied file. The whole 31-byte header is the GCM associated data.

### 1c · The `CLOUD_BACKUP` consent gates the file-picker backup too

The plaintext export (ADR-0023) is not consent-gated; the backup is. Same picker, different purpose:
an export is a file the user chooses to read, a backup is meant to be elsewhere — and the picker can
return a cloud drive as easily as a memory card, indistinguishably. The consent is read **before** the
archive, and revoking it drops a sealed backup still waiting for the picker. The persisted id stays
`cloud_backup`; the label becomes "Save encrypted backups off this device".

### 1d · The passphrase is consumed

Text fields hold it while typed (Compose needs a `String`); the create event clears both fields in the
same update that shows "sealing" and hands a `CharArray` to the repository, which zero-fills it in a
`finally`. Derived key and plaintext bytes are zeroed too. 12-character floor on `seal` only — never on
`open`.

### 1e · Irrecoverability is an acknowledgement, not a recovery phrase

SEC-005: "the recovery phrase screen makes irrecoverability explicit". A generated recovery phrase
would be a second secret that also opens the backup. The requirement is the explicitness, so the
create button stays disabled until the user ticks the sentence saying a lost passphrase is a lost
backup.

### 1f · A backup is audited

`AuditEvent.BACKUP_CREATED`, best-effort — a failed audit write never discards a backup that exists.

### 1g · The BouncyCastle family resolves as one version

The first full `unitTests` run failed fifteen `:feature:dashboard` Compose tests with
`NoClassDefFoundError: … compositesignatures.KeyFactorySpi` — a module this issue never touched.
Cause: Robolectric depends on `bcpkix`/`bcutil` 1.79 and something else on `bcprov` 1.81; bumping our
`bcprov` to 1.86 upgraded only that jar, and Robolectric's `BouncyCastleProvider` initialisation broke
on the mismatch. Pinning our version back to 1.81 would have hidden it (and tripped lint's
`NewerVersionAvailable`); instead the root build aligns every `org.bouncycastle:*-jdk18on` request to
the catalog version.

### 1h · Where it lives

Settings, below the app lock — F6's flow starts at "Settings → enable backup". `:sync:backup` stays a
placeholder: nothing here is a worker, and the nightly / server-blind blob paths are later issues.

## 4 · Quiz

**Outcome: not yet taken.** The answers in italics are the author's; the pass CLAUDE.md §10 asks for
is the developer answering these before reading them. Record the result here, fails included.

1. Why can't `BackupCipherTest`'s KDF vectors be generated by running `BackupKdf` once and pasting
   the output? *(They would pin whatever the code does, including a wrong lanes/memory mapping; OpenSSL
   is an independent implementation.)*
2. A file's header says 4 GiB of memory. What happens, and before what? *(`Validation("backup.format")`,
   before any key is derived or memory allocated.)*
3. Why does a wrong passphrase and a flipped tag bit return the same error? *(Distinguishing them tells
   an attacker which one they got right.)*
4. Why is there no passphrase length check in `open`? *(A later policy change must not lock anyone out
   of a backup they already made.)*
