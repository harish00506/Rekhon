## Acceptance Criteria

- [x] Linking a txn/account updates goal progress exactly (sum of contributions, `Money` paise).
      Verified on the emulator: a ₹10,000 SIP link moved a goal from ₹10,000 to ₹20,000, to the paise.
- [x] Unlinking reverses it; provenance is retained; per-profile scoped. Reversal is a **soft
      delete**, so the figure drops by exactly what it rose by and the link keeps its `created_at`;
      every query is scoped by `profile_id` and a link forged under another profile does not count.
- [x] Covered by tests including reversal — 17 repository cases over real SQL, 9 ViewModel, 12
      Compose, 8 new engine cases, 3 golden records, a 21→22 migration round trip.
- [x] Golden rules (P-01...P-08) respected. **MNY-001 trivially**: no new column holds money, because
      a contribution *is* the linked transaction. **TIM-001/002**: the clock is injected and both
      date bounds are ISO days. **P-03**: no figure is invented — an unknown salary day produces
      silence. **P-04**: exercised in airplane mode.
- [x] All Skill Rules and label-specific rules below are satisfied. The `new-engine` skill does not
      apply: this adds no engine module, because summing linked rows is what a repository already
      does for balances (ADR-0007).
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11). **Step 12 stands**: nothing is
      committed until the user asks.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **P-07 Advice, never orders** - the app recommends and simulates; the user decides. No auto-executed money movement.
