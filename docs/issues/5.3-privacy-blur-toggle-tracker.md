## Acceptance criteria

- [x] **The toggle blurs every monetary value app-wide; state persists in DataStore.** Both
      rendering paths converted — `CfoAmountText` (14 sites) and `maskedAmount(...)` (~24 sites, the
      `stringResource` placeholders that a component alone cannot reach). Persisted through the
      `privacy_blur_enabled` field reserved since issue 1.9; proven to survive a force-stop on
      device. Editable amount fields are exempt by design (see the issue file).
- [x] **Combined with FLAG_SECURE (11.2) so amounts are not captured.** `PrivacyCaptureGuard` sets
      it from the same flag; `adb exec-out screencap` returns **0 bytes** while blurred. 11.2 still
      owns the always-on policy and the recents guard.
- [ ] **Honoured by the widget** — **not met, and not tickable.** `:widget` is a bare
      `ModulePlaceholder`; the Glance widget is issue **5.5**, unbuilt. Carried there rather than
      claimed here.
- [x] **A Compose UI test asserts amounts are hidden; an accessible label is present.**
      `DashboardPrivacyBlurTest` sweeps every rendered string for `₹`-plus-digit and asserts the
      TalkBack label reads "Amount hidden" rather than the figure. The toggle reports its own on/off
      through `stateDescription`.
- [x] **Golden rules respected; money/time rules hold.** No figure is computed or altered — the mask
      is applied at the render boundary only (P-03); the sign survives so direction is never colour
      alone (P-02); nothing leaves the device (P-01).

## Carried forward

- **Issue 5.5 (Glance widget)** inherits "the widget honours the blur". It must read
  `SettingsStore.privacyBlurEnabled` and render the mask from cached values; the widget module is
  still a placeholder today.
- **Issue 11.2 (FLAG_SECURE)** supersedes `PrivacyCaptureGuard`'s decision — always-on or not,
  per-screen exemptions, and the recents thumbnail. There is one place that sets the flag, so it
  replaces rather than fights.
- **A lint rule banning `MoneyFormatter.format` inside a `@Composable` in `:feature:*`** would turn
  this issue's convention into a build gate. The dashboard sweep covers one screen; the others rely
  on the convention holding. Recorded in ADR-0022's follow-ups; not filed as an issue yet.
- **`CfoSmokeTest` is not hermetic about app data** — it skips its demo-entry branch when the app is
  already onboarded, so a device someone has been driving by hand fails it. Cost a re-run in both
  the 5.2 and 5.3 sessions.
