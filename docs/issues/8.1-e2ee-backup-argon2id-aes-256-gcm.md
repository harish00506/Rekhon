## Description

End-to-end-encrypted backup: passphrase → Argon2id KDF → AES-256-GCM (via Tink) over the exported archive - the platform never sees plaintext or key.

## Acceptance Criteria

- [x] Backup encrypts the archive with AES-256-GCM keyed by an Argon2id-derived key (Tink; no hand-rolled crypto, SEC-003). — Tink `AesGcmJce`; Argon2id from BouncyCastle because Tink has none (ADR-0039), checked against OpenSSL.
- [x] A unique IV/nonce is used per backup; the passphrase is never stored; off-device writes are consent-gated (P-01). — fresh salt + Tink nonce per seal (tested, and seen on two device files); passphrase zero-filled on every path; `CLOUD_BACKUP` checked before the archive is read.
- [x] Round-trip decrypt test; a tampered tag is rejected. — `BackupCipherTest` (29), plus the device-made file opened independently with OpenSSL + Python AES-GCM, wrong passphrase and flipped tag rejected.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched. — no amounts or dates are computed; no network path; works in airplane mode.
- [x] All Skill Rules and label-specific rules below are satisfied. — restore atomicity is 8.2's (it applies `open` through the archive import); `open` already fails secure with no partial output.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`). — see the tracker's Verification Log.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.
