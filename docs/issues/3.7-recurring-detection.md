## Acceptance Criteria

- [x] The detector is deterministic (fixed input → fixed output, P-08) and emits provenance + evidence.
      `RecurringInput` takes `nowUtcMillis` rather than reading a clock; shuffled and reversed input
      give an identical result, provenance included; every series carries `EngineProvenance` citing
      `RULE-RECUR-DETECT@1.0`, the date window read, and a confidence in basis points.
- [x] It detects fixed and near-fixed cadences within a tolerance and does not false-positive on
      one-offs. Golden case: a frozen ten-row ledger proposing exactly three series. Refusals under
      test: a single transaction; two identical amounts to *different* merchants; two charges 40 days
      apart; a blank merchant; one irregular gap in an otherwise clean series.
- [x] The user can confirm/reject; decisions feed back as data, not code. A decision is a
      `recurring_rule` row (`is_confirmed` / `dismissed_at_utc_millis`), and `observeDecidedNames`
      reads it back on the next emission — proven on the device by rejecting a proposal, leaving the
      screen and re-opening it.
- [x] Golden rules (P-01...P-08) respected. No network on any path (P-01/P-04, verified in airplane
      mode); every figure from deterministic math (P-03); the card shows its evidence (P-02); it
      proposes and never creates (P-07); money is `Long` paise with no floating point and no division
      (MNY-001), tolerances are integer percent and confidence is basis points (MNY-002), the clock is
      injected (TIM-001) and dates are ISO strings (TIM-002).
- [x] All Skill Rules and label-specific rules satisfied: one public interface with an `internal`
      implementation behind a factory (ARC-003); pure Kotlin, no Android imports (ARC-002); the
      repository is the only DAO toucher (ARC-005); `ENGINE.md` written; the rulebook threshold is a
      data row, mirrored per ADR-0005 and guarded by a drift test.
- [x] Definition of Done met. Phase 8's `:app:connectedDebugAndroidTest` turned out to have had no
      `androidTest` source set at all — it ran zero tests and reported success — so this issue added
      `CfoSmokeTest` and the gate now runs 2/2 against the real Hilt graph and the real encrypted
      database. See the tracker.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **AI-ARC-003/006** - every engine result carries provenance (engineId/version/inputWindow/computedAt/confidence/evidence).

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

representative amount was reverted to a signed median. The dismissal exclusion was proven on the
device rather than only in a test.
