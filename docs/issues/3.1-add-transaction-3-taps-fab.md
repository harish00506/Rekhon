## Acceptance Criteria

- [x] Add-txn is reachable and completable in ≤ 3 taps (a Compose UI test asserts the tap count).
      **Two** for a common expense — 1 FAB + 1 Save. The count is asserted across two files, because
      the FAB lives in `:app` and a feature module may not see it (ARC-001):
      `AddTransactionFabTest` (`:app`) pins the first tap, `AddTransactionFlowTest`
      (`:feature:transactions`) pins the rest. Both name the shared budget so neither reads as the
      whole assertion. Confirmed on the emulator.
- [x] Amount is `Money` paise; date via the injected `Clock`; the write goes through the repository.
      Parsed once by `MoneyFormatter.parse` at save (never a `Double`); `occurredAtUtcMillis` from
      `clock.nowUtcMillis()` (TIM-001) and `bookedOn` from `clock.today()` (TIM-002, pinned by a test
      that books at 00:30 IST / 19:00Z the previous day).
- [x] Validation for empty/invalid amount; fully offline. Zero, blank and over-precise amounts are
      refused with **nothing written**; an unknown or soft-deleted account is `NotFound`. The whole
      emulator run was in airplane mode (P-04).
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched.
      No network on the path; errors cross layers as `AppError.code`, never a message (P-01); the id
      and both timestamps come from injected sources, so the write is reproducible (P-08).
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`) — **except step 10's
      merge/push**, which awaits the user's instruction (step 12).

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **§21.6 theming/i18n** - strings in `strings.xml` (ICU plurals); colours/dimensions from theme tokens.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. ≤ 3 taps is a hard requirement (FR-TXN-002); amounts are `Money` (MNY-001).

### Label-specific

1. Every user-visible string lives in `strings.xml` with ICU plurals; colours/dimensions come from theme tokens (§21.6).
2. UiState is one immutable data class exposed as `StateFlow`; events flow up via a sealed interface (ARC-004).

### Epic-specific
