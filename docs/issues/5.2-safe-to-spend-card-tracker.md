## Acceptance criteria

- [x] **Safe-to-Spend is computed deterministically from nature + upcoming commitments (P-03), in
      `Money` paise.** `SafeToSpendEngine` (AI-STS) takes six `Money` terms; `spentToDate` is issue
      4.3's `NatureBreakdown.trueSpend`, and commitments are future-dated rows plus confirmed
      recurring rules. No clock, no randomness — 500 seeded property months assert same-in/same-out.
- [x] **The card shows the breakdown/rule that produced it (P-02); never a black-box number.**
      `SafeToSpend.lines` is part of the result and its constructor asserts the signed lines sum to
      the headline. The card renders each line signed, plus `RULE-STS v1.0`.
- [x] **Golden-file test; airplane-mode safe.** 12-record fixture fixing the breakdown as well as the
      figure; the whole path is local reads and pure arithmetic, verified with the device in
      airplane mode.
- [x] **Golden rules respected; money/time rules hold.** `Long` paise throughout, buffer as bps with
      `HALF_EVEN`, `nowUtcMillis` passed in and never read for a decision, every window resolved from
      the injected `Clock` inside the repository.

## Prerequisite fix carried by this issue

`TransactionRepository.observeNatureBreakdown()` (issue 4.3) ran to the **month's last day**, so a
payment scheduled for the 28th was reported on the 3rd as money already spent — on a card captioned
"This month, *actually*", against FR-TXN-010 — and was then deducted a second time by this issue's
scheduled-payments term. Bounded at `MonthWindow.actualsEndIsoDate`, the bound `observeMonthCashFlow`
three methods below has always used.

Fixed here rather than filed, because 5.2's terms cannot be made disjoint without it and the change
is one expression. It does change the "This month, actually" figures for any user with a future-dated
row in the current month — recorded in the CHANGELOG and
[ADR-0021](../adr/0021-safe-to-spend-buffer-and-goal-stand-in.md).
