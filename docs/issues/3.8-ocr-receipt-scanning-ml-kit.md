## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.

**Done, 2026-08-06.** All green; the full timestamped log is in the tracker.

```text

./gradlew verifyPaparazziDebug                            OK
./gradlew :domain:engines:receipt:test                    OK  (incl. the >= 95% eval gate)
./gradlew :core:database:connectedDebugAndroidTest        OK  (15 tests, incl. the 10 -> 11 round trip)
./gradlew :app:connectedDebugAndroidTest                  OK  (smoke + the real-image OCR check)
python -c "import json;json.load(open('ai/rules/rules-kb.json',encoding='utf-8'))"   OK
```

**Three gates were made to fail on purpose before being trusted:** the rulebook drift test (moved
`low_confidence_bps`), the >= 95% eval gate (mis-labelled three fixtures), and the blob-erase
regression test (removed the file-name sanitising).

**The emulator run is what found the three real defects** — two-column recognition, the clipped
trailing zero, and the refusal to back-date a receipt (**ADR-0011**). Every unit test was green
before it. §9's "a green build does not close the issue", literally.

**Not verified on a device:** the camera capture path. The emulator's camera renders a synthetic
scene rather than a receipt, so the gallery path was exercised instead; the two share the intent
contract, the `FileProvider` grant and the byte read.

Full timestamped log: [3.8-ocr-receipt-scanning-ml-kit-tracker.md](3.8-ocr-receipt-scanning-ml-kit-tracker.md#verification-log).
