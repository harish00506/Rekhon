## Acceptance Criteria

- [x] The LLM runs on-device behind the `LlmEngine` interface; cloud is opt-in and receives only the structured context pack (§19.4), never raw transactions (P-01) — the port is in `:domain:engines:chat`, the shipped implementation is `:ml:llm`'s deterministic verbaliser, and `VerbalisationDraft` **is** the context-pack type: the intent and the tool results, nothing else. **Cloud assist is deferred** (ADR-0053): the payload type exists, the transport does not, and nothing leaves the device.
- [x] Answers are produced by calling registered tools; every figure comes from an engine and passes the guardrail (P-03/AI-ARC-004) — `ChatToolExecutor` is the complete list of what chat may read, and `compose()` builds AI-GRD's allowlist from the tool results and nothing else.
- [x] Covered by tests with a stubbed LLM; the offline path works — 67 tests across four modules, and the offline path **is** the shipped path: the verbaliser needs no network and no model file.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched — amounts stay `Money` paise from tool to guardrail; the engine is pure and takes `nowUtcMillis` (P-08); no network on any path (P-01/P-04); chat never writes to the ledger (P-07).
- [x] All Skill Rules and label-specific rules below are satisfied — one public interface plus result types, `internal` implementation behind `ChatEngineFactory`, provenance on every reply naming the model and the rules.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`) — see the Verification section below.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **AI-ARC-003/006** - every engine result carries provenance (engineId/version/inputWindow/computedAt/confidence/evidence).

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. On-device by default; the LLM verbalises, never computes (P-01/P-03).

### Label-specific

1. The LLM never computes a figure - it verbalises engine output, gated by the guardrail (P-03/AI-ARC-004).

### Epic-specific

1. Advisors simulate and recommend - never execute money movement (P-07); the LLM only verbalises (P-03).
