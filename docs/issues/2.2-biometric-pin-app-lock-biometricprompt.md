## Acceptance Criteria

- [x] BiometricPrompt (class 3) unlocks; a PIN fallback covers no-biometric devices; lock on cold start and a configurable idle timeout.
  - `AppLockGate` shows `BiometricPrompt` with `setAllowedAuthenticators(BIOMETRIC_STRONG)` and a
    "Use PIN" negative button. `TinkPinVerifier` is the fallback. Cold start is locked because
    `SessionLock` starts closed; the idle timeout is §23.1's 60 s default, configurable and stored.
  - **Caveat:** the prompt itself has never been executed - no device or emulator. See the tracker.
- [x] Failure is fail-secure (no data shown on cancel/error); lockout after repeated failures.
  - 21 cases in `AppLockViewModelTest`: wrong PIN, cancelled biometric, broken Keystore and an
    unreadable settings file all leave the app `LOCKED`. SEC-002's 5-failures -> 30 s doubling is
    pinned attempt by attempt in `LockoutPolicyTest`, and survives a restart.
- [x] No biometric material leaves the device; auth events go to `audit_log` with no PII.
  - Nothing touches a biometric template - the platform decides and reports a boolean.
    `audit_log` (schema v2) has four columns and stores closed-enum **codes**; a test asserts the
    real SQLite columns, so there is nowhere to put PII.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched.
  - `money-time-audit` clean. No wall-clock read outside the injected `Clock` (TIM-001); `LockoutPolicy`
    is pure and deterministic (P-08); nothing leaves the device (P-01); no network on any path (P-04).
- [x] All Skill Rules and label-specific rules below are satisfied.
  - No hand-rolled crypto: Tink primitives only (SEC-003). No PII in logs - there is no `Log.*` call
    in any of the new code.
- [ ] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).
  - Every gate green **except step 9's emulator run**, which is blocked rather than skipped: no
    device exists on this machine. The tracker lists exactly what that leaves unproven.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.
