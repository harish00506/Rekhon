## Acceptance Criteria

- [x] OSV scans dependencies in CI; new criticals block the build (SEC-007). `scanDependencies` resolves every module's **release-runtime** classpath (278 coordinates — resolved, not requested, so a transitive upgrade cannot hide) and fails on anything at or above HIGH that is not allowlisted. The CI step is deliberately **not** `|| true`, which the placeholder it replaced suggested. Proven non-vacuous by scanning known-vulnerable coordinates: 56 blocking findings, exit 1. **"Could not reach OSV" exits 2, not 0** — a scanner that passes when it cannot scan would be green on every offline machine forever.
- [x] The release build is R8-minified with PII/amount log stripping **verified** (§21.6). 84.5 MB → 66.6 MB, and `Log.v/d/i/w`, `isLoggable` and `println` are absent from the shipped DEX — checked by parsing the APK, not by trusting the rule file, because a rule file is not evidence about a binary. `Log.e`/`wtf` are kept on purpose. The checker is proven non-vacuous against the unminified debug APK, where it finds all six and fails.
- [x] New third-party deps are justified in the issue — **none were added.** Standard-library Python only: no Gradle vulnerability plugin (a build dependency, a feed and a plugin to keep current, for forty lines against OSV's public API) and no pytest (for twenty-two assertions `unittest` already covers). ADR-0062 tabulates both rejections. No `DECISIONS.md` dependency row is required.
- [x] Golden rules (P-01...P-08) respected. No amount or date is computed here. **P-04 is respected precisely by the scan failing offline rather than passing:** P-04 is a promise about the *app*, which still works in airplane mode — it is not a licence for a security gate to go green when it cannot check anything.
- [x] All Skill Rules and label-specific rules below are satisfied — no crypto was touched, and the release now has no chatty log surface at all.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

**The thing this issue found.** A clean install of the minified release opened on the lock screen **with no PIN set** — a total lockout — while the same commit as a debug build opened on onboarding. protobuf-javalite resolves its generated classes reflectively, R8 renamed them, the settings read failed, and the app lock's fail-secure default did exactly what it promises over data it could not trust. No crash, nothing in logcat, and nothing in 5,102 JVM tests could see it, because they all run on unminified code. Fixed with a keep rule carrying the evidence that produced it (ADR-0062).

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. Deps are scanned; the release strips PII/amount logs (SEC-007/§21.6).

### Label-specific

1. No hand-rolled crypto - Tink/Keystore only (SEC-003); no PII/amounts in release logs.
2. All CI gates green before merge; no new lint/detekt warnings (§21.6).

### Epic-specific

1. Privacy and security are fail-secure and consent-first; no hand-rolled crypto anywhere (P-01/SEC-003).
