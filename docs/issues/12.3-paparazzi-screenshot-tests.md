## Acceptance Criteria

- [x] Screenshot tests cover design-system components + critical screens (light/dark/200%). The design system was already covered; this issue added **the three critical flows `CLAUDE.md` §4 names** — add-transaction, onboarding and the purchase advisor — which had **no render at all**. **26 committed baselines, up from 11.**
- [x] Diff failures block merges; baselines are checked in. `verifyPaparazziDebug` was already inside `unitTests` and named in CI, so this was true before the issue — and it is now **proven**: changing the advisor's padding fails the build, and deleting one baseline fails the build.
- [x] The update flow is documented — `docs/testing/screenshot-tests.md`, including why recording stays manual and the three mistakes already made in this repo.
- [x] Golden rules respected. **P-02 is what this issue actually serves:** "show the work" is a claim about what a user can *read*, and on the advisor — the densest screen in the app — a figure that clips is reasoning the user cannot check. MNY-001's Indian digit grouping (`₹1,00,000.00`) is now visible in a committed render rather than only asserted.
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

**What the very first 200% render found.** The purchase advisor's "Urgent" chip broke mid-word across three lines — `Ur` / `ge` / `nt` — because the chips sat in a fixed `Row` that squeezed the last one instead of wrapping. **No unit test could have caught it:** the text was correct, the semantics were correct, every existing assertion passed. Fixed with `FlowRow`, the idiom `:feature:budgets` already used, and verified in the re-recorded baseline.

**This project has no emulator in CI.** These renders are the only way anyone sees the UI before it ships, which is why the gap on the critical screens mattered more here than it would elsewhere.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **§21.6 theming/i18n** - strings in `strings.xml` (ICU plurals); colours/dimensions from theme tokens.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. DS components have screenshot tests; diffs gate merges (§21.5).

### Label-specific

1. Golden-file + property + seeded-determinism tests; engine coverage ≥ 85%, money math 100% (§21.5).
2. Every user-visible string lives in `strings.xml` with ICU plurals; colours/dimensions come from theme tokens (§21.6).
3. UiState is one immutable data class exposed as `StateFlow`; events flow up via a sealed interface (ARC-004).

### Epic-specific

1. Tests gate merges: coverage, screenshot diffs, AI-eval thresholds, and the airplane-mode E2E (§21.5).
