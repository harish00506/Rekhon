## Acceptance Criteria

- [x] The key is generated in the Keystore (StrongBox when present) and is never exported or logged (SEC-003). — `KeystoreMasterKey` asks the platform's own `KeyGenerator` for the key **before Tink looks for it**, with StrongBox where the device advertises it; a Keystore key cannot be exported by construction, and no log line anywhere carries key material. **An existing alias is never replaced** (`MasterKeyPolicy`), because that would orphan the keyset, the passphrase and the database.
- [x] A rotation path re-keys the DB without data loss (tested); the StrongBox-absent fallback is documented. — the two-slot protocol stages the new key, calls SQLCipher's own `changePassword`, then promotes; `KeyRotationTest` proves on a device that every row survives **and** that the old key no longer opens the file. The fallback is in ADR-0057 §1 and is the path that actually ran on the emulator.
- [x] Security-review sign-off recorded. — run with the `security-review` skill: no high-confidence vulnerabilities, two defence-in-depth findings fixed, one library assumption verified in the artifact. ADR-0057 "What the review checked", and the tracker's log.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched. — no money or dates are touched; `SecureRandom` for key material, never the injected seedable source (P-08's rule is for engines, and a predictable key is a vulnerability); nothing leaves the device (P-01); the path has no network and works in airplane mode (P-04).
- [x] All Skill Rules and label-specific rules below are satisfied. — Tink/Keystore only; the one place that touches the cipher is `DatabaseRekeyer`, and it calls the library's own re-key rather than composing SQL with a key in it.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.
