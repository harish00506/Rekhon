## What is proven, and what is not

**Proven on the JVM (285 tests, every one of them run):**

- SEC-002's schedule, attempt by attempt — 5 failures → 30 s, then 60 s, 120 s, 240 s, capped at an
  hour, with the overflow case that a naive `shl` would wrap open.
- The fail-secure matrix, 21 cases: a wrong PIN, a cancelled biometric, a Keystore that has stopped
  working, and an unreadable settings file **all leave the app locked**, and each is audited.
- The lockout survives a restart (a fresh store over the same file still reports it) — which is the
  property that makes it worth anything at all.
- The PIN never appears in the stored credential, and two devices with the same PIN store different
  bytes.
- The PIN is never written to `SavedStateHandle` (asserted against every key in the bundle).
- `audit_log` holds only codes and a timestamp — asserted against the real SQLite columns, not the
  entity declaration.
- The §23.1 auto-lock timer re-locks past the timeout and does not on a brief task switch.

**Not proven — the honest gaps:**

1. **`BiometricPrompt` has never executed.** No device, no emulator (`adb devices` empty, no AVD).
   Everything around it is tested, but the callback wiring itself — the single most security-critical
   piece, where "not an error" must not be read as "authenticated" — has only been reviewed, not run.
2. **The real Android Keystore has never been touched.** `TinkPinVerifier` is tested against a fake
   Tink `Mac`, because a TEE does not exist off-device. `KeystoreMacFactory` is branch-free by
   design, precisely so this gap is as small as it can be, but it is still untested code.
3. **The v1 → v2 migration has never run.** `MigrationSafetyTest` proves the schema change is
   structurally non-destructive on the JVM, and the hand-written DDL was diffed against Room's own
   generated `createSql` by hand (they match exactly). `MigrationRoundTripTest` — which would prove
   the rows survive — needs a device.
4. **The gated database provider is checked once, not continuously.** `@Singleton` caching means the
   assertion runs at the first injection, so it proves "nothing read financial data before the first
   unlock" but not "nothing reads it after an idle re-lock". Recorded as the accepted limitation in
   [ADR-0003](../adr/0003-app-lock-gate-and-deferred-user-auth-key.md).
5. **SEC-001's "requiring user authentication" clause remains open**, deliberately — ADR-0003
   decision 1. This issue does **not** close SEC-001.
6. **`:core:crypto` has no coverage floor.** `configureCoverage()` is only applied by the
   *pure-Kotlin* convention plugin, so Android library modules get Kover with zero rules — the same
   shape of hole as governance audit G-01. `LockoutPolicy` and `TinkPinVerifier` are exhaustively
   tested by hand, but nothing in the build would notice if those tests were deleted. Pre-existing,
   not introduced here, and worth its own issue.
7. **CI has still never run.** No git remote; every green is a local green on one Windows machine.
