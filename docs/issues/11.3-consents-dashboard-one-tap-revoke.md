## Acceptance Criteria

- [x] Every consent (SMS, network, backup, cloud LLM ...) is listed with state + timestamp; one-tap revoke takes effect immediately (P-01). — all four, **including the ones nobody has answered for** (absence is never consent), each with the date it was given and, when it applies, the date it was withdrawn. The rows come from the store's own flow, so "immediately" is literal: the screen changes when the ledger does, not before.
- [x] Revoking disables the dependent feature and stops its data flow at once. — enforced where each data path lives, by code that predates this issue and has tests naming the behaviour: SMS drafts erased and the cursor reset, no price fetched, no backup written off device. `CLOUD_LLM` has no enforcement because it has no transport, and the screen says exactly that. Tabulated in ADR-0059.
- [x] Covered by tests; strings externalised. — 15 tests (7 state, 8 rendered) with 5 mutations; 20 strings, in English, Hindi, Kannada and Tamil, held by issue 10.8's coverage gate.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched. — no money; the dates are rendered in the **profile's** zone from the injected `Clock` (TIM-001) and carried as ISO date-only strings (TIM-002); one immutable `UiState` as a `StateFlow` with events up a sealed interface (ARC-004).
- [x] All Skill Rules and label-specific rules below are satisfied. — the security review found no vulnerabilities; its two observations are in ADR-0059 (the row that must not flip before the store agrees, and a read failure that must not read as "nothing granted").
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. Consent is explicit, per-feature, and revocable (P-01).

### Label-specific

1. No off-device data flow without explicit, revocable, per-feature consent (P-01).
2. Purpose-limited, consent-based, rights-respecting data handling (DPDP 2023 / P-01).

### Epic-specific

1. Privacy and security are fail-secure and consent-first; no hand-rolled crypto anywhere (P-01/SEC-003).
