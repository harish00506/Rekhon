## Bugs found while building this

1. **A derived category id collided with the row a delete had just soft-deleted.** Created ids were
   `category:<slug>-<createStamp>`; deleting "Fuel" and recreating it in the same millisecond
   produced the same primary key, so `REPLACE` resurrected the deleted row with its old nature.
   Found by `a name freed by a delete can be used again`. Fixed by using the injected `IdGenerator`
   for user-created rows (seeded ids stay derived, which is what makes the seed idempotent).
2. **A categorised transaction rendered as "Uncategorised."** `ListRow`'s title fell back
   note → merchant → "Uncategorised" and never consulted the category — harmless while no real
   profile could have one, false the moment the seed landed. Found on the emulator, fixed, and pinned
   by `a categorised row is named after its category, not called Uncategorised`.
3. **The editor sheet could not scroll.** The screen was a `LazyColumn` with the sheet above it, so
   at 200% font Save was unreachable. Found by `performScrollTo` failing in the Compose test; fixed
   by making the whole screen one scrolling `Column` (a taxonomy is tens of rows — laziness bought
   nothing).
4. **Two buttons labelled "Delete" on screen at once** — the row's action and the confirmation's.
   Ambiguous to read and worse to hear announced. Found by the Compose test failing with "found 2
   nodes"; the confirm now reads "Delete it" against "Keep it".
