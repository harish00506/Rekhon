## Acceptance Criteria

- [x] N split lines sum exactly to the parent over random n/amount (property test, MNY-001).
      `SplitTest`'s property test asserts it on the rows **read back out of SQLite**, not on `Money`
      — `MoneySplitPropertyTest` already proves the arithmetic, so re-proving it would have tested
      nothing new. A draft whose lines miss by one paise is **refused with nothing written**.
- [x] The remainder is distributed largest-remainder-first (`Money.split`), so a 3-way split of 1000 is 333.34/333.33/333.33; each line carries its own category/nature.
      Observed on the emulator via **Split evenly**. The generated instruction to use HALF_EVEN here
      was wrong and is corrected at source — see [ADR-0009](../adr/0009-splits-as-a-child-table.md).
- [x] Editing a line re-balances; the UI shows the running remainder.
      "Remaining ₹1,000.00" with Save disabled → ₹0.00 with Save enabled, recomputed on every
      keystroke from parsed lines (never stored, never rounded).
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched.
      Amounts stay text until save (MNY-001); the whole emulator session ran in airplane mode (P-04);
      the split's exactness is decided by integer comparison, not a tolerance (P-08).
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`), and step 12 —

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. Splits always sum to the parent; use `Money.split`/`allocate` (MNY-001).

### Label-specific

1. Money is `Long` paise end-to-end; no `Double`/`Float` on a monetary value (MNY-001).
2. Splits distribute the remainder (largest-remainder, `Money.split`/`allocate`) so parts sum exactly; HALF_EVEN is for rounding a single value (`Money.percentOf`), and cannot make N parts sum to a whole.

### Epic-specific

1. Add-txn stays ≤ 3 taps; every captured record is provenance-tagged by source (FR-TXN-002/FR-TXN-009/AI-ARC-003).

**On the emulator, in airplane mode throughout (P-04):**

| Step | Observed |
|---|---|
| Install **v6** (built from `dev`), add a ₹777 expense | net worth **₹4,16,485.00** |
| Install v7 **over** it, no uninstall — the DB-003 check | opens; net worth **unchanged**; nothing lost |
| ₹1,000 → **Split into lines** | two lines seeded; the parent's category row disappears |
| Before any line amount | **Remaining ₹1,000.00**, Save **disabled** |
| Three lines → **Split evenly** | **333.34 / 333.33 / 333.33**, Remaining **₹0.00**, Save enabled |
| Save → list | **one** row, "3 lines", −₹1,000.00; the day total counts it **once** |
| Delete it → Accounts | Cash Wallet −₹5,236 → **−₹4,236**: back by exactly ₹1,000 |

That last pair is the whole design in two numbers — the split moved the balance **once**, by the
parent amount, and the lines moved nothing.
