## Acceptance Criteria

- [x] A transfer debits source and credits destination as one linked record, excluded from income/expense totals.
      Two rows sharing a `transfer_id`, written inside one `withTransaction` (DB-004), typed
      `transfer_out`/`transfer_in` so `type IN ('expense','income')` excludes them. Verified on a
      device: HDFC ₹3,82,800 → ₹3,77,800 and Cash −₹4,236 → +₹764 from one save.
- [x] The amounts balance exactly in `Money` paise (property test).
      `TransferTest.the legs of any transfer sum to exactly zero` walks magnitudes from one paise to
      a crore and asserts the pair folds to `Money.ZERO` with checked arithmetic (MNY-001).
- [x] Soft-deleting a transfer reverses both legs atomically.
      One `UPDATE … WHERE transfer_id = ?`, so no window exists where one leg is gone and the other
      is not. Asserted from **both** legs, and observed on the emulator: deleting the row put both
      balances back to the paise.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched.
      Both legs share one injected-`Clock` instant and one profile-zone booked day (TIM-001/TIM-002);
      ids come from the injected generator (P-08); cross-currency transfers are refused rather than
      converted at a made-up rate (P-03); the entire emulator run was in airplane mode (P-04).
- [x] All Skill Rules and label-specific rules below are satisfied.
      `room-and-migrations`: schema 5 → 6 with an exported, committed `6.json` and a device round-trip
      test; **non-destructive** (DB-003), proven by installing v6 over a v5 install with real data.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`). Merged `--no-ff`
      into `dev`; push skipped because the repo has no remote.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).
