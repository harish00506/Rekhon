## Requirement-ID correction (recorded per workflow step 3)

The generated issue doc cited **FR-TXN-004**. That is wrong: FR-TXN-004 is *split transactions*
(issue 3.3). The requirement this issue implements is:

> **FR-TXN-002 (MUST)** — "Add-transaction MUST be reachable in one tap (FAB) and completable in
> ≤ 3 taps for a common expense (amount → category suggestion → save)."

Also in scope: **FR-TXN-001** (the fields captured) and **FR-TXN-009** (every transaction records its
source; this flow writes `manual`). Fixed at source in
[`scripts/gen_issue_docs.py`](../../scripts/gen_issue_docs.py) and regenerated — the epic-3 rule line
carried the same wrong id and was corrected too.

## Defects found and fixed

Three, and **none of them was caught by the build** — all three came from driving the running app,
which is exactly why step 9's emulator run is the real gate.

1. **Every demo transaction was invisible in the recent list.** `transactions.source` has held
   `"demo"` since issue 2.4 (`SOURCE_DEMO` in `:data:repository`). The first `TransactionSource`
   enum modelled only FR-TXN-009's four values plus `reconciliation`, so the mapper's
   forward-compatible `mapNotNull` silently dropped all of them — a demo profile whose account
   balances plainly derived from those rows showed "No transactions yet".
   *Lesson recorded in the enum's doc comment: grep what the app already writes to a column before
   modelling that column as a closed set.* Regression test:
   `the demo's own history is inside the window`.
2. **Save was unreachable behind the keypad** on a profile with four accounts and twelve categories.
   The app draws edge-to-edge, so the IME overlays the window rather than resizing it; without
   `imePadding()` the scrollable Column believed it had the full screen and had nothing to scroll.
   The short form a new user sees hid this completely.
3. **A double-tap on Save booked the spend twice.** The write completes fast enough that the second
   event arrives *after* `isSaving` has cleared, while the screen is still leaving. `isSaved` is now
   guarded as well. Caught by `a second Save while one is in flight writes nothing extra`.
