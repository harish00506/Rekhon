## Decisions worth recording

- **The `Clock` reads a cached zone, not a blocking one.** `Clock.zone()` is synchronous because
  every engine calls it inside ordinary maths; the setting arrives as a `Flow`. An app-scoped
  collector keeps the zone in a `@Volatile` and the clock reads that. `runBlocking` is banned
  outside tests (§5) and would block startup on a disk read; making `Clock` suspend would ripple
  through the whole domain layer.
- **Every zone failure falls back to the device zone.** Unset, unreadable, or unparseable — an
  exception out of `Clock.zone()` would crash every engine at once, while a slightly wrong day
  boundary is recoverable.
- **The DI cycle is cut with `Provider<SettingsStore>`.** `Clock` needs the zone provider, which
  needs settings, which are built beside the consent store, which needs `Clock`. Deferring the
  lookup to `start()` is the honest fix — by then the graph is complete.
- **`provideDatabase` throws on `Err`.** An app that ran without its database would show an empty
  net worth and no transactions, which reads as data loss rather than a fault. A crash report is
  better than a silently empty app.
- **Navigation extensions were dropped after a compiler crash.** Registering destinations directly
  in `:app` is simpler and satisfies ARC-001 just as well — features never import each other either
  way.
- **`RoomDatabase` moved to `api` in `:core:database`.** A type in a module's public surface cannot
  be an implementation detail; the DI graph must be able to see it.
- **No device-only tests were written.** The screens are covered by the ViewModel's Turbine tests
  and the design system's screenshots; adding unrunnable Compose UI tests would be dead code today.
