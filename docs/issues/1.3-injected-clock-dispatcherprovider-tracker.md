## Decisions worth recording

- **`java.time`, not `kotlinx-datetime`.** minSdk 26 has `java.time` natively (NFR-008), so the
  pinned §21.3 stack needed no new dependency — and adding one would have required an ADR.
- **A project-owned `Clock` interface rather than `java.time.Clock`.** The zone is *profile* state,
  not JVM state; `java.time.Clock.fixed()` cannot advance; and the SRS names this API.
  `SystemClock` is implemented over `java.time` underneath.
- **Profile zone behind `zoneProvider: () -> ZoneId`,** re-read on every call, defaulting to the
  device zone. That is the seam Proto DataStore settings (issue 1.9) plug into; nothing of 1.9 is
  built here.
- **Calendar helpers are extension functions,** so the injected interface stays three methods wide
  and an implementation has only those three to get right.
- **`FakeClock`/`TestDispatchers` ship from `testFixtures`** so later modules inject the same
  doubles. Consequence discovered while verifying: Kover counts `testFixtures` classes, so a
  published fixture needs its own tests — done rather than excluded, since the fixture has logic
  every module will depend on.
- **`DefaultDispatcherProvider` reads each dispatcher on access, never in a constructor.** Plain
  JVM has no `Dispatchers.Main` factory, so eager resolution would throw in any unit test that
  never touches the UI; the test installs one with `Dispatchers.setMain`.
