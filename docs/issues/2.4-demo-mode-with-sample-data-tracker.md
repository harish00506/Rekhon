## What is proven, and what is not

**Proven on a device for the first time in this project.** The app builds, installs, launches, and
the whole demo round trip works — including in airplane mode. Issues 1.x–2.3 all shipped with this
gate logged as blocked; it is no longer blocked, and the `docs/memory.md` line claiming no `adb` and
no AVD was simply out of date.

**Two things that had never actually run anywhere, and now have:**

- **The Room migrations.** `MigrationRoundTripTest` needs a device, so v1→v2 and v2→v3 had only ever
  been asserted by the JVM-side `MigrationSafetyTest` (which checks the *statements*, not the
  result). Both now execute against real SQLite and preserve their rows. DB-003 is no longer taken
  on trust.
- **The Keystore PIN path.** `OnboardingFlowInstrumentedTest` sets a PIN through the real
  `TinkPinVerifier` over the real Android Keystore and verifies it back out. Every JVM test of this
  path uses a fake `Mac`, because a TEE does not exist off-device — so until now SEC-002's
  credential storage had no execution anywhere.

**Proven on the JVM, not on the device:** the *residue* claim. `DemoModeRepositoryTest` runs against
real SQLite (Robolectric, unencrypted in-memory) and asserts zero rows remain. The encrypted
on-device database cannot be queried from `adb` without rooting, so the device evidence is
behavioural (exit returns to onboarding; re-entry rebuilds cleanly), not a row count.

**Found and fixed, not part of the issue:** `OnboardingFlowInstrumentedTest` had not compiled since
issue 2.3 — `OnboardingViewModel`'s constructor changed under it and nothing noticed, because
`androidTest` is only compiled when a device is attached. This is the same class of governance gap
as audit G-01: a gate that is documented as existing but never runs. It compiles and runs now.

**Still open:** CI has never run (no git remote), so every green remains a local green on one Windows
machine.

**Worth fixing in a later issue (found here, not fixed):** only `:core:database` and
`:feature:onboarding` have `androidTest` sources, but a project-wide `connectedDebugAndroidTest`
builds, installs and instruments a test APK for **every** Android module — several minutes each,
finding nothing. That is what made the first attempt unusable. Either scope the command to the two
modules or stop generating empty test APKs.
