## Acceptance criteria

- [x] **Export writes a versioned JSON archive locally; import restores it losslessly (round-trip
      test).** `ArchiveRepositoryTest` exports a profile with a row in **every one of the fourteen
      tables**, wipes, imports, and compares row for row. Verified on device: 99 rows out, 99 rows
      back, and a transaction added in between correctly gone.
- [x] **`Money` stays paise; the schema is versioned; there is no network path (P-01/P-04).**
      `ArchiveFormatTest` pins `amountMinor` as an integer; the envelope carries `archiveVersion` and
      `schemaVersion`, and an archive from another schema is refused by name. The repository returns a
      `String` — the screen writes it through the system file picker, and there is no network code on
      this path.
- [x] **Handles empty and large datasets; covered by tests.** An empty profile round-trips and
      invents nothing; 2,000 transactions survive, which is what proves the import holds inside one
      transaction rather than tripping SQLite's variable limit.
- [x] **Golden rules respected; money/time rules hold.** Nothing is computed — the archive copies
      stored values, `Money` stays `Long` paise and dates stay ISO strings (MNY-001, TIM-001/002).
      The destructive half is unreachable without a second, explicit tap (P-07).

**Deliberately excluded, argued in [ADR-0023](../adr/0023-archive-replaces-and-carries-no-blobs.md):**
receipt image bytes (a plaintext file must not carry decrypted receipts off the device — the rows
travel, the blobs do not) and `audit_log` (no `profile_id`, so the schema cannot scope it).

## Carried forward

- **Issue 8.1 (E2EE backup)** can encrypt this same archive rather than inventing a second format,
  and should carry the receipt blobs this one deliberately does not. `:sync:backup` is still a
  `ModulePlaceholder`, untouched by this issue.
- **A `schemaVersion` migration path** becomes real the first time the schema moves after an archive
  exists in the wild. Today there is one version and refusing anything else is the honest behaviour;
  the field exists so a future build can do better.
- **`ArchiveFormatTest` covers the envelope and the transaction row**, not all 156 columns. That
  would be a file nobody maintains; the round trip already covers *loss*, and this covers the fields
  whose meaning an old file depends on.
