## Decisions worth recording

- **The harness is two halves, and that is the point.** Room's `MigrationTestHelper` needs a device;
  this project has none, which would have left DB-003 enforced by nobody. But the exported schema
  is *data*, and `room-migration` parses it in plain Kotlin — so "no table or column may disappear
  or change type" is checked on **every build, everywhere**, and only the row-level "the data
  actually survived" check waits for hardware.
- **Four things count as destructive:** a dropped table, a dropped column, a changed SQL affinity,
  and a nullable column made `NOT NULL` (which passes on an empty database and fails on real data).
  Additive changes are allowed, because a guard that blocks safe work gets switched off.
- **The check is structural, so a rename-with-copy will be flagged.** Deliberate bias: the fix is to
  prove the data survives in the device test, not to loosen the guard.
- **Schema-level money/time invariants are asserted too** — `*_minor` and `*_utc_millis` must be
  INTEGER, `*_iso_date` must be TEXT, every table needs `deleted_at_utc_millis` and (except
  `profile`) `profile_id`. The 1.5 lint rules guard the Kotlin side; this guards the column that
  actually stores the value, where a `REAL` amount would do the damage.
- **A version bump cannot silently skip its fixture:** the fixtures must be contiguous from 1 and
  must include the declared version, so forgetting to commit the JSON fails the build.
