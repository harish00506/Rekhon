## Decisions worth recording

- **`MoneyFormatter` lives in `:core:model`, not the UI layer.** Issue AC3 requires Indian grouping;
  sub-task 1.1.2 said formatting belongs at the UI edge. The issue wins, and `java.text`/`BigInteger`
  are JVM stdlib, so ARC-002 (no Android imports) still holds and engines can format for exports too.
- **Grouping is hand-written, not delegated.** `DecimalFormat` supports a single grouping size
  (verified: it emitted `₹123,456.78`), and `NumberFormat(en-IN)` depends on platform locale data
  that differs across JDK and Android releases. The 2,2,3 rule is written out so output is identical
  everywhere and safe to assert on.
- **`BigDecimal`/`BigInteger` are used internally** in `percentOf` and the formatter — never on the
  public API, which AC4 is what actually forbids. They buy exact HALF_EVEN rounding and a safe
  `abs(Long.MIN_VALUE)` without a single floating-point operation.
- **Kover has no per-rule class filter in 0.9** (checked against the plugin API, not assumed), so
  "money math 100%" is enforced as "the money module is 100%" — the stricter reading.
- **No ADR** (`Money` as `Long` paise comes *from* SRS §21.4; `CLAUDE.md` §5 requires an ADR only for
  a deviation) and **no ENGINE.md** (`Money` is a primitive, not an engine).
