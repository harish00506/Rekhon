### Observed but not attributed

On first launch after install, the app sometimes crashes with
`IllegalStateException: The encrypted database was opened while the app was locked (SEC-002)` from
`AppLockGate` → `hiltViewModel()` → `CoreModule.provideDatabase`. It reproduced twice, then **zero
times in eight further cold installs** across both configured and unconfigured builds, and 0/5 warm
launches. The stack trace contains nothing from this issue. Recorded because it was seen; a relaunch
clears it. This is consistent with the cold-install flakiness already measured for `CfoSmokeTest`
(6 failures in 10 cold-install runs, commit `46850fa`).

### Still open

- **No public deployment.** `backend/README.md` holds the ordered steps; they need a hosting account
  and a domain.
- **`gold:` is untested live** — it needs a provider API key. The parser is tested against a recorded
  payload; the live call has never been made.
- **First `mf:` request after a restart takes ~3.5 s** (AMFI's 1.5 MB file) against API-001's
  five-second client budget. Degrades to the cached price; the next request takes 0.18 s.
