## Acceptance Criteria

- [x] Consent records, purpose strings, and rights flows (access via export 5.4, erase 11.4) are mapped to DPDP requirements — `docs/compliance/dpdp-2023.md` §1–§3. The mapping also **closed a gap it exposed**: the consent record had never reached the export, so the right of access returned the user's data while keeping the record of what they had agreed to. It now ships in `CfoArchive.consents`, and is deliberately **never imported** (ADR-0061).
- [x] A compliance doc/ADR traces each requirement to its implementation — and the doc is **machine-checked**. `DpdpComplianceDriftTest` fails the build if a `ConsentFeature` has no row, if the document names a consent that does not exist, if any cited class or test stops existing, or if the four open obligations stop being listed as open.
- [x] No off-device processing without a lawful consent basis (P-01) — tabulated in §1. The default binding `UnconfiguredMarketDataApi` makes **no** network call; the one configured call is consent-gated and carries only a `PriceKey`, whose character set cannot hold an amount or a name.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched. No amount is computed here. Timestamps are UTC epoch millis in the archive (TIM-001), matching every other field in it — the *screen* is where a date becomes a day in the user's zone, which is ADR-0059's rule and deliberately not repeated in a machine-readable file.
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

**Stated plainly:** four DPDP obligations are **not met** and cannot be met by code in this repository — grievance redressal (§13), nomination (§14), breach notification (§8(6)) and children's data (§9). They are listed as open in the compliance document's §4, with what each would need, and a test keeps them listed. A compliance document that overstates is worse than none.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).
