## Acceptance Criteria

- [x] Future-dated txns are excluded from actuals - balance, net worth and day totals - until their date passes (FR-TXN-010, injected `Clock`, TIM-001).
      **Only half of this was already true.** Net worth bounded on `booked_on_iso_date` since 2.6;
      the *account-balance* queries did not, so the first scheduled payment would have been
      subtracted on the accounts screen while net worth showed a different figure for the same money.
      Both are bounded now. Verified on the emulator: net worth held at ₹4,16,485.00 with ₹25,000
      scheduled.
- [x] A scheduled txn is visible and labelled as scheduled, and is readable by forecasts before its date (FR-TXN-010's second clause).
      A **Scheduled** group above a **Posted** one, its day headers deliberately carrying no total.
      `TransactionRepository.observeUpcoming()` is the seam Epic 6's forecast and FR-HOME-001's
      14-day card read.
- [x] Rollover needs no write: the same row counts on its own date. A daily WorkManager job records the posting idempotently, but no balance depends on it having run (ADR-0010).
      Proven by advancing the emulator's date one day: net worth moved ₹4,16,485.00 → ₹3,91,485.00,
      exactly ₹25,000, with nothing written. `ScheduledTransactionWorker` stamps `posted_at`; a
      second run the same day stamps nothing.
- [x] Covered by boundary tests (today vs tomorrow, zone/DST-safe).
      `FutureDatedTransactionTest` — 22 cases, including today-vs-tomorrow on the balance, the
      profile-zone rollover at 23:30 IST while UTC is still on the previous date, and Chile's
      2026-09-06, a day whose local midnight does not exist.
- [x] Golden rules (P-01...P-08) respected; money/time rules hold wherever amounts or dates are touched.
      Every date goes through the injected `Clock` (TIM-001); the whole emulator session ran in
      airplane mode (P-04); the worker logs no row count (§21.6).
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. Date logic via the injected `Clock`, never `System.currentTimeMillis()` (TIM-001).
2. Never gate an amount on a background job: a deferred worker must not change a figure.

### Label-specific

1. Match existing conventions; ship the smallest correct diff (`/ponytail`).

### Epic-specific

1. Add-txn stays ≤ 3 taps; every captured record is provenance-tagged by source (FR-TXN-002/FR-TXN-009/AI-ARC-003).
