## Acceptance Criteria

- [x] CI enforces all gates; coverage and AI-eval thresholds block merges. **Already true before this issue** — `koverVerify` (engine ≥ 85%, money 100%) and `aiEval` have been blocking since 1.2 and 12.2. Said plainly rather than claimed as new work. This issue adds the tenth gate, `verifyReleaseMetadata`, and tabulates all of them in `docs/releases-process.md` §1.
- [x] The release train bumps `VERSION`/`versionName`/`versionCode` and updates `CHANGELOG.md` per SemVer (§26). `scripts/release.py` writes `VERSION`, sets `versionCode` to one above the ledger's highest, and appends the ledger row; `versionName` needs no bump because it already reads `VERSION` at build time. **It was dogfooded: this issue's own 0.12.4 → 0.12.5 / code 63 bump was performed by it.** It deliberately does **not** generate the changelog entry — those are release notes, and a generated line is worse than none because it looks like documentation.
- [x] A tagged release build is produced and documented. The release APK is produced and log-strip-verified in the gate run, and tagging is documented in `docs/releases-process.md` §3. **No tag was created, and that is deliberate:** tags belong to a promotion, where `stage`/`main` are protected and a human is in the loop, and a tag on `dev` would assert a release that did not happen. **This repository has no tags at all, because nothing has been promoted past `dev`** — a true statement about the project rather than a gap in the process (ADR-0068).
- [x] Golden rules respected. P-08 in the sense that matters here: the release metadata is now a **fixed input → fixed output** check rather than a judgement someone makes each time. No amount or date is computed.
- [x] All Skill Rules and label-specific rules below are satisfied.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

**What reconstructing the history found — two drifts, neither ever noticed.**

1. **Epic 11's seven issues shipped as `0.10.8`–`0.10.14`**, under the Epic 10 heading, when `00-issue-workflow.md` says "starting a new Epic → minor bump +0.1.0". That makes it a documented-rule violation, not a style preference.
2. **Ten versions shipped with a `versionCode` that did not increase** — `0.3.10`, `0.3.11` and `0.4.0` all carried 18. Google Play rejects such an upload **after** a release has been cut.

**Both are left exactly as they are**, marked in `docs/releases.md` and explained in `docs/releases-process.md` §4. Renumbering released versions would make the changelog disagree with the commits it documents, and none of the stalled codes was ever uploaded — this app has not shipped.

**And the first version of the gate did not catch the drift it was built for.** Comparing an entry's minor with its heading's minor passes `### [0.10.11]` under `## [0.10.0]` happily, because both say 10. The thing that was wrong is that it delivered **Issue 11.4**. The rule now parses the issue id from the title. Found by running the implementation against the repository's own history rather than against its tests.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.

## Workflow Rules — While Solving

### Universal (apply to every issue)

1. Define expected vs actual behaviour with evidence (logs, tests).
2. Reproduce before fixing; binary-search to isolate the root cause.
3. Form testable hypotheses; switch to formal debugging after 10 min of guessing.
4. Smallest correct diff; match the surrounding code style.
5. Verify the fix with the original reproduction case.
6. **Respect the boundaries** - `feature → domain → data/core` (ARC-001); engines pure-Kotlin (ARC-002); repositories are the only DAO touchers (ARC-005).

### Issue-specific (from the SRS)

1. All gates green before release; `VERSION` is the single source (§21.6).

### Label-specific

1. All CI gates green before merge; no new lint/detekt warnings (§21.6).

### Epic-specific

1. Tests gate merges: coverage, screenshot diffs, AI-eval thresholds, and the airplane-mode E2E (§21.5).
