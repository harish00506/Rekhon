## Decisions worth recording

- **Paparazzi 2.0.0-alpha02, not the 1.3.5 stable.** 1.3.5 cannot run on Gradle 8.13. The choice was
  an alpha or no visual coverage; since this is test-only tooling that ships in no APK, and since
  there is no emulator, the alpha wins. Revisit when 2.0 is stable.
- **The 200%-font screenshot earned its place immediately.** It caught an amount wrapping
  mid-number on its first run — a defect no unit test would have found and no reviewer would have
  noticed without rendering it.
- **P-02 is built into `CfoAmountText`:** the sign is always rendered and colour only reinforces it,
  so debit/credit survives colour-blindness, greyscale and the privacy-blur mode.
- **Copy stays out of the design system.** Components take their text and `contentDescription` as
  parameters, because only the calling screen knows the wording and only its `strings.xml` should
  hold it (§21.6). Charts make `contentDescription` **required** — a chart is invisible to a screen
  reader otherwise.
- **48dp is a token, not a habit.** `CfoDimens.minTouchTarget` is applied by every clickable
  component, so the most commonly failed accessibility rule is stated in one place.
- **No dynamic colour (Material You).** It would recolour `positive`/`negative` from the user's
  wallpaper — the two colours in a finance app that must stay distinguishable and contrast-checked.
- **Two chart primitives, not a charting framework** (your call). Anything more waits for issue 5.1,
  where a real screen states a real requirement.
- **No device-only Compose UI tests were written.** They would be unrunnable code with no signal
  today; the DoD's "≥ 1 Compose UI test **or** screenshot test" is satisfied by the screenshots.
