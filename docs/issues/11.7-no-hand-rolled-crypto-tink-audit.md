## Acceptance Criteria

- [x] The audit confirms every crypto operation uses Tink/Keystore; a lint check flags raw `javax.crypto` misuse (SEC-003). Full record in [`docs/security/sec-003-crypto-audit.md`](../security/sec-003-crypto-audit.md): ten production files touch cryptography, every cipher/AEAD/MAC is Tink's, every key is in the Keystore, and a grep for `Cipher.getInstance`, `MessageDigest`, `javax.crypto.Mac`, `SecretKeySpec` and the parameter specs returns **nothing**. `CfoHandRolledCrypto` (ERROR, every module) now flags them, matching **resolved types rather than identifier names** — `import javax.crypto.Cipher as Box` would defeat a name-based security rule.
- [x] Findings are resolved and a security-review sign-off is recorded — §5 of the audit, with four findings. Two were pre-existing and argued (Argon2id from BouncyCastle, ADR-0039; the Keystore `KeyGenerator`, ADR-0057); one was that SEC-003 was **unenforced**, now fixed; one came from a mutation — see below.
- [x] A test/CI rule prevents regressions. 11 detector tests, 4 audit-inventory drift tests, and — crucially — the rule **proven to fail a real `lintDebug`** on a seeded `Cipher.getInstance`, not only the test harness. `lintDebug` already runs in CI.
- [x] Golden rules (P-01...P-08) respected. **P-08 shaped the rule:** `SecureRandom` is deliberately *not* flagged, because P-08 requires randomness from an injected, seedable source and all four uses here are injected — a rule banning it would fight the rule it serves. No amount or date is touched.
- [x] All Skill Rules and label-specific rules below are satisfied — the `security-review` checklist drove §1's three-pass method.
- [x] Definition of Done met (`00-issue-workflow.md` steps 9-11; `/pre-merge`).

**The audit found no bug — and that was the problem.** SEC-003 was true and unenforced: nothing in the build checked it, so the conclusion would have started decaying the day after it was written. That is the fifth instance of this shape in this project (1.5, 7.2, 11.5, 11.6), and this issue's own mutation found a sixth: **a detector could be removed from `CfoIssueRegistry` with all 25 lint tests still green**, because every test passes `.issues(X.ISSUE)` and bypasses the registry — the only thing that makes a rule apply to a build. That exposed all five pre-existing rules, not just the new one. Two registry tests now pin publication and ERROR severity.

## Guiding Principles (CLAUDE.md §1 / design spec §2)

- **P-03 Numbers from math, words from AI** - engines compute every figure; the LLM only verbalises.
- **P-01 Privacy first** - no financial data leaves the device without explicit, revocable, per-feature consent.
- **P-02 Show the work** - every output shows its inputs + the rule/model that fired + a plain-language reason.
- **P-08 Deterministic & testable** - fixed input → fixed output; randomness only via an injected, seedable source.
- **SEC-003 / P-01** - Tink/Keystore only (no hand-rolled crypto); every off-device path is consent-gated.
