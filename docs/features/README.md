# Feature & Task Breakdown — AI Personal CFO

The entire SRS, decomposed into the smallest shippable units of work.

```
Epic (= SRS Phase, §26)  →  Feature (a coherent capability)  →  Task (smallest unit, one slice)
```

> **Canonical backlog is now the reference-style spec + CSV.** The authoritative epic → issue
> index lives in the design spec [`../superpowers/specs/2026-07-17-ai-personal-cfo-design.md`](../superpowers/specs/2026-07-17-ai-personal-cfo-design.md)
> §13 and its machine-readable [`../superpowers/specs/2026-07-17-issues.csv`](../superpowers/specs/2026-07-17-issues.csv)
> (13 epics, 85 issues), with one rich [`../issues/<id>-<slug>.md`](../issues/) + `-tracker.md`
> per issue (generated by [`../../scripts/gen_issue_docs.py`](../../scripts/gen_issue_docs.py)).
> **This `docs/features/` tree is the deeper sub-task layer** those issues link *down* into — e.g.
> issues 1.1–1.5 link to the Feature 1.1 task files below. Add task files here just-in-time when
> an issue is too large for one PR. (The 6-Epic phase view below predates the 13-epic backlog and
> is kept as the phase-oriented map; the CSV is the source of truth for IDs.)

- Each **task** is one focused, independently testable change — spec'd in full (objective,
  skills, rules, tests, DoD) using [`_TASK_TEMPLATE.md`](_TASK_TEMPLATE.md).
- Execution & verification for a feature is driven through the issue workflow
  ([`../issues/00-issue-workflow.md`](../issues/00-issue-workflow.md)); each feature has an issue +
  tracker.
- IDs are stable: `E.F.T` (Epic.Feature.Task). Cite them in commits and the `CHANGELOG.md`.
- **Status legend:** ⬜ todo · 🟡 in-progress · ✅ done · ⛔ blocked.

> Task files are authored **just-in-time** as each epic is reached, from the template — so the
> spec stays accurate to what's known then. Epic 1 is fully broken to task files below; Epics 2–6
> are enumerated to feature level with their SRS requirement IDs and seed tasks.

## How to work a feature/task
1. Pick the next ⬜ task whose dependencies are met.
2. Open its task file; follow the **Skills & commands** order and **Rules** section.
3. Create/append the feature's issue + tracker (`../issues/`), branch `feature/<E-F-T>-<slug>`.
4. Tests first → implement → run on emulator (`/run`, `/verify`) → `/pre-merge`.
5. On Done: bump `VERSION` + `CHANGELOG.md`, update the tracker, mark the task ✅ here.
